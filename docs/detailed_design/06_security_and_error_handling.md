# 安全边界与异常处理详细设计

## 1. 目标

将 PR 标题、描述、diff、源代码、仓库文件名和 Agent 工具参数全部视为不可信输入，在保留审查能力的同时限制数据泄露、提示词注入和命令执行风险。

## 2. 信任边界

| 边界 | 不可信内容 | 防护措施 |
| --- | --- | --- |
| 本地仓库到 Agent | 源码注释、diff、提交信息、文件名 | 以数据形式提供；系统指令禁止执行仓库内指令。 |
| 本地用户到 CLI | 仓库路径、ref、配置路径 | schema 校验、Git ref 校验、路径约束。 |
| Agent 到工具 | 工具参数 | schema 校验、路径约束、命令 allowlist。 |
| 服务到模型供应商 | prompt、代码上下文 | 最小必要传输、secret 脱敏、可配置供应商。 |

## 3. 提示词注入防护

- 系统指令明确：仓库内容仅为待审查数据，不能改变角色、工具权限或输出规则。
- 对模型输入使用明确分隔的 `DIFF`、`FILE_CONTENT`、`PR_METADATA` 区段；不把其中的文本提升为指令。
- Agent 只能调用注册工具，不能调用网络、shell 或写文件工具。
- 发现仓库内容试图诱导泄露密钥、跳过规则或执行命令时，将其视为可疑文本而非操作指令。

## 4. Secret 与隐私

- 不读取仓库外文件、用户主目录或进程环境变量内容。
- 写入日志、trace、可选持久化记录、终端中间结果和最终报告前，使用可配置规则遮蔽常见 token、私钥和连接字符串。
- 模型 API Key 和其他本机 secret 永远不进入 prompt、报告、异常栈或 trace 属性。
- 对客户代码的保留时长和模型供应商传输范围应在部署配置中明确。

## 5. 异常模型

定义 `ReviewError` 基类，并分为：

- `ConfigurationError`：YAML、环境变量、模型映射和参数错误。
- `RepositoryError`：非 Git 仓库、ref 不存在、路径越界、Git 执行失败。
- `ToolError`：可恢复的工具调用失败。
- `ProviderError`：认证、限流、超时、模型不支持。
- `IntegrationError`：webhook、checkout、评论发布或持久化失败。

每个异常应携带稳定 `code`、面向用户的安全消息、是否可重试以及底层原因链。底层命令完整输出只可进入受控调试日志，不能直接展示或发送给模型。

## 6. 重试与降级

只对幂等且可重试的 provider 错误重试，例如限流和短暂网络失败；使用 `review.provider_retry_*` 配置控制有限次数的指数退避加抖动。认证失败、非法配置、路径越界和不允许的命令不可重试。

未能完成独立验证时，默认不发布未验证 finding；详见 [多 Agent 审查编排](04_multi_agent_review_orchestration.md)。

## 7. 测试与验收

- 覆盖路径逃逸、恶意 ref、命令注入样式输入和超大 diff。
- 验证日志与异常文本不含模拟 token 或 private key。
- 验证可重试与不可重试错误的次数、状态和最终 CLI 退出码。
